# E2B 兼容 Sandbox Runner

E2B runner 将执行环境放到远程 sandbox。Worker、Workspace、Pipeline 和 Codex app-server 协议继续共用现有执行流程；服务通过 sandbox API 管理实例，通过 envd 传输进程输入、输出和文件。CloudPilot 服务使用 Go 客户端，Node.js 只用于构建模板及 sandbox 内的 Worker。

## 配置 Novita

导入 [Novita 资源示例](../examples/novita.yaml) 前，先构建 Worker 模板，填写模板 ID 或别名，并在 CloudPilot 服务环境中配置密钥。`apiKeySecretRef` 保存环境变量名，不保存密钥值。Sandbox 管理凭据与 Worker 模型凭据分别配置，可以引用不同变量。

```yaml
apiVersion: cloudpilot.dev/v1alpha1
kind: Runner
metadata:
  name: novita-sandbox
spec:
  type: e2b
  e2b:
    provider: novita
    domain: us-phx-1.sandbox.novita.ai
    apiKeySecretRef: NOVITA_SANDBOX_API_KEY
    template: cloudpilot-codex
    leaseSeconds: 900
    idleStrategy: pause
```

| 字段 | 说明 |
| --- | --- |
| `provider` | `e2b` 或 `novita`，默认 `e2b`；选择对应协议配置 |
| `domain` | Sandbox 域名，不带协议、端口或路径；Novita 默认 `us-phx-1.sandbox.novita.ai`，E2B 默认 `e2b.app` |
| `apiUrl` | 可选的管理 API 地址；默认 `https://api.<domain>`，可独立覆盖 |
| `apiKeySecretRef` | 必填；CloudPilot 服务中保存管理 API key 的环境变量名 |
| `template` | 必填；当前服务商账号和区域内的模板 ID 或别名 |
| `leaseSeconds` | 默认 900，允许 60–86400；服务商账号可能限制更小的值 |
| `idleStrategy` | 当前仅支持 `pause` |

`type: e2b` 不接受 Docker 的 `image`、`network`、`memory` 和 `cpus` 字段。CPU、内存和基础依赖在模板构建时指定。

Novita v2 的默认区域是 `us-phx-1`；旧区域使用 `sandbox.novita.ai`。区域版本与管理 API 路由版本分别配置：`provider: e2b` 的创建、连接分别使用 `/v2/sandboxes`、`/v2/sandboxes/{id}/connect`；`provider: novita` 使用兼容路由 `/sandboxes`、`/sandboxes/{id}/connect`，创建时启用 secure access。Novita 的 v2 区域不表示所有 URL 都要加 `/v2`。配置中的 `apiUrl` 只填写管理 API 的基地址，路由由客户端添加。参考 [Novita 概览](https://docs.novita.ai/guides/sandbox-overview)。

## 模板与模型

[deploy/sandbox](../deploy/sandbox) 提供 Novita 模板构建脚本，使用 `node:24-bookworm-slim`，预装 Codex 0.166.0、Git 和 GitHub CLI 2.103.3。模板以非 root 的 `user` 运行，该用户拥有可写的 `/workspace`、`/output`。模板不包含模型、GitHub 或 sandbox 管理密钥；任务启动时按资源中的环境变量引用注入所需凭据。模板构建只在发布或升级执行环境时进行，每轮运行复用已构建的模板。

构建机器需要 Node.js 24 和 npm。在仓库根目录执行：

```sh
sh deploy/sandbox/build.sh \
  --name cloudpilot-codex \
  --image public.ecr.aws/docker/library/node:24-bookworm-slim \
  --key-file /path/to/novita-key \
  --output /tmp/cloudpilot-template.json
```

`--image` 默认是 `node:24-bookworm-slim`。上例使用 Docker 官方镜像的 ECR 镜像源；服务商构建环境遇到 Docker Hub 认证异常时，可通过这个地址拉取同一基础环境。

也可预先设置 `NOVITA_API_KEY`，然后省略 `--key-file`。`--domain`、`--api-url` 分别覆盖 sandbox 域名和管理 API 地址，默认使用 Novita v2。脚本临时安装固定版本的 `novita-sandbox@2.1.2`，结束后删除该依赖目录；不会给 CloudPilot 服务新增 Node SDK 依赖。构建进程通过 Node.js 的 `NODE_USE_ENV_PROXY=1` 使用环境代理配置。

脚本向 stderr 输出构建日志，成功时输出包含 `templateId`、`buildId`、区域地址及 `status: "ready"` 的 JSON。将 `templateId` 填入 [examples/novita.yaml](../examples/novita.yaml) 的 `spec.e2b.template`，替换 `REPLACE_WITH_BUILT_TEMPLATE_ID`，再导入资源。构建期间输出文件的状态为 `building`；脚本等待超过 20 分钟会停止等待并保留构建 ID，此时应先检查原构建状态，再决定是否重新构建。

示例分别引用 `NOVITA_SANDBOX_API_KEY`、`NOVITA_LLM_API_KEY` 和 `NOVITA_WEBHOOK_SECRET`。在 CloudPilot 服务环境中提供这三个变量；同一个 Novita 账号 key 可以通过前两个变量分别供管理 API 和模型 API 使用。Webhook secret 使用单独的随机值。需要操作私有仓库时，再为 Workspace 配置对应的 `secretEnv` 引用。

模板需支持 envd 的非 PTY stdin、stdout/stderr 分离和 stdin EOF。Codex app-server 通过 JSONL 双向通信，PTY 的回显与换行转换不适用于该通道。模板或服务商升级后应重新执行协议集成检查。

Novita 模型 API 与 sandbox 管理 API 使用不同地址：

| 用途 | 地址 |
| --- | --- |
| Novita v2 sandbox 管理 | `https://api.us-phx-1.sandbox.novita.ai` |
| Codex 的 Responses API base URL | `https://api.novita.ai/openai/v1` |

Worker 示例：

```yaml
spec:
  type: codex
  model: deepseek/deepseek-v4.1-flash-1017
  endpoint: https://api.novita.ai/openai/v1
  apiKeySecretRef: NOVITA_LLM_API_KEY
```

Codex 使用 `wire_api = "responses"`；`endpoint` 填 base URL，由 Codex 添加 `/responses`。这里不能照搬 Chat Completions 示例中的 endpoint 路径。配置方式见 [Novita Codex 接入](https://docs.novita.ai/guides/codex)。

## 跨轮状态与清理

交互式会话按 AgentSession 保留 sandbox，不按 Workspace 资源在多个 Run 之间共享实例。每轮启动新的 app-server 进程，保留 `/workspace` 中的仓库和 Codex 会话数据，重新准备本轮 `/output`，先收集产物、清理本轮进程，再暂停 sandbox。下一轮连接同一实例并继续会话。需要跨轮使用的文件放在 `/workspace`，交付文件放在 `/output`。批处理执行完成或取消后删除其 sandbox。

Sandbox 的 pause 保存文件、内存和进程状态，并中断网络连接。CloudPilot 的进程监督器会在轮次结束时清理同一进程组，以及继承本轮运行标记的 detached 进程；主动清除标记并离开进程组的程序无法保证被全部清理。系统文件和已安装软件也会跨轮保留，因此隔离与重置边界是整个 AgentSession，不具备 Docker 每轮重建容器的完整重置语义。模型密钥、仓库凭据和临时文件应按会话的隔离范围管理。Novita 的持久化行为见 [暂停与恢复](https://docs.novita.ai/guides/sandbox-pause-resume)。

“中断当前轮次”保留工作目录，等待人工继续；“结束任务”删除保留的 sandbox。删除后的实例和文件不可恢复，已下载的产物及历史运行记录仍保存在 CloudPilot。删除已知 ID 的实例后会再次查询，确认服务商返回不存在；失败会保留清理状态和错误。

创建请求超时或连接中断时，服务可能还没有拿到 sandbox ID。CloudPilot 会按部署和执行尝试的 metadata 查询实例，避免重复创建。对启用自动暂停的会话，租期到期不代表实例被删除；查询不到匹配实例时仍保留待清理状态，后续重试核对。

后台维护每分钟重试未完成的清理，并检查保留会话是否仍存在。直接在服务商控制台删除实例等情况会使会话进入 `workspaceLost` 状态；界面和 API 禁止继续该会话，仍允许“结束任务”。开始新的 Run 才会创建新工作目录。

数据库和 `runtime.data_dir/e2b/runtime-id` 必须一起保留，用于核对当前部署拥有的远程实例；该标识与 Docker 的 `runtime.data_dir/runtime-id` 独立。恢复时应还原完整数据目录、对应数据库以及所需凭据，远端 sandbox 也必须仍然存在。服务重启后，中断的 Agent 轮次等待人工继续，避免重复执行已经发生的外部操作。多个 CloudPilot 服务实例共享调度数据库的限制仍然适用。

## 超时与费用

`Pipeline.timeoutSeconds` 限制一次 Agent 轮次；`leaseSeconds` 控制远程实例的续租窗口；网络请求超时、进程流超时和服务商最大会话时长也各有含义。执行期间需要续租，空闲时通过 pause 保留现场。续租不保证能够突破账号的最大会话限制，也不应把“有客户端连接”当作任务仍有有效进展。

Novita 官方配额当前列出 Free 最长会话 1 小时、Paid 3 小时、Enterprise 默认 4 小时且可调整。实际部署以账号、区域和最新配额为准，长任务应预留收集产物与清理时间。参考 [Timeout Handle](https://docs.novita.ai/guides/sandbox-timeout-handle) 和 [Quota Limits](https://docs.novita.ai/guides/sandbox-quota-limit)。

Pause 停止计算计费，但暂停实例、模板和快照仍产生存储费用。Pipeline 并发限制只限制活动任务，不能限制积累的暂停实例数量。为保留会话制定存储预算和关闭周期，及时通过“结束任务”回收不再使用的实例；检查清理失败的记录和服务商账单。参考 [Novita 计费说明](https://docs.novita.ai/guides/sandbox-overview)。

## 验收

日常单元测试不需要云端凭据。更换服务商、模板或协议版本后，应运行真实集成检查。准备同时具有目标区域 sandbox 权限和模型 API 权限的 Novita key 文件，并将模板 ID 设置为构建脚本返回的值：

```sh
export CLOUDPILOT_E2B_TEST_KEY_FILE=/path/to/novita-key
export CLOUDPILOT_E2B_TEST_TEMPLATE=your-template-id

go test ./internal/runtime -run '^TestE2BLive(InteractiveFixture|BatchAndCancellation)$' -count=1 -timeout 15m -v
go test ./internal/runtime -run '^TestE2BLiveCodexDeepSeek$' -count=1 -timeout 15m -v
```

第一组使用确定性的 Worker fixture，检查批处理、取消、交互控制、暂停、服务重建恢复、跨轮文件与历史产物、脱敏和删除确认；只使用 sandbox 资源。第二组通过真实 Codex app-server 调用 `deepseek/deepseek-v4.1-flash-1017`，检查两轮会话保持同一 thread、同一 sandbox 和工作文件，并验证产物收集及关闭。它同时消耗 sandbox 和模型额度。

上述检查已在 Novita v2 和构建的 Codex 0.166.0 模板上通过：

- 交互式 fixture 完成三轮，包括补充信息、打断、暂停、重新创建运行时并恢复；sandbox、thread 和工作文件保持一致，历史产物未被覆盖，日志中的密钥已脱敏。
- 批处理退出码为 7 时仍收集产物；取消执行后删除实例。
- 真实 Codex 与 DeepSeek 完成两轮：首轮写入工作文件和产物，恢复后第二轮读取同一工作文件并生成独立产物。结束任务后查询返回 404。

所有测试创建的 sandbox 均已确认删除。其他服务商或模板需要重新验收，不能从 Novita 的结果推断全部扩展能力都兼容。

测试会清理其创建的实例；若测试进程被强制终止，应根据 `/tmp/cloudpilot-e2b-live-*.json` 中的部署和实例记录核对服务商资源。未设置这两个环境变量时，真实集成测试自动跳过。
