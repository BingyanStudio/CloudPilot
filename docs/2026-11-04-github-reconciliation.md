# GitHub 工单状态核对

GitHub issue 任务在首次执行和人工续轮开始前读取最新工单；运行中的任务以 30 秒间隔安排核对。已有任务收到通过签名校验的 issue Webhook 时，会提前安排核对，包括关闭、移除标签和撤销指派。只认创建任务时持久化的 GitHub 关联，普通 Webhook 中的 `source` 字段不能启用 GitHub 访问。

工单必须仍然开放，并满足 Input 当前配置中的任一 assignee 或 label 条件。首次执行前不再符合条件的事件变为 `cancelled`，不会创建 Run 或消耗 attempt；排队中的人工续轮及运行中的交互任务变为 `interrupted`，保留工作目录、会话与已收集产物。工单重新符合条件后，可由管理员继续原会话；没有开放会话的已取消事件可重新入队。重复 Webhook 本身不会自动重放任务。

GitHub 请求最多等待 10 秒，不阻塞人工控制和运行进度持久化。每个调度周期最多发起 4 次检查，其中活动任务最多使用 2 次，按距离上次检查的时间排序；其余额度留给新任务及续轮。每个周期轮换首先调度的 Pipeline，避免单个持续积压的队列占用全部核对额度。大批量任务和慢 API 会延后实际检查时间。网络、认证、404、限流及异常响应均视为无法确认状态；排队工作延迟 30 秒再检查，按可执行时间排序让后面的任务继续前进，运行中的工作继续执行。相关错误及尚未创建 Run 的取消原因记录在服务日志中。凭据使用 Input 当前配置，支持轮换；关联工单 ID 变化时也停止新的调度并等待处理。

核对不能撤销 Agent 已经提交到外部服务的操作。Pipeline 暂停或定时等待期间，排队任务在实际获得调度机会时检查；Input 暂停仍只控制 Webhook 接收，不会取消已开始的工作。
