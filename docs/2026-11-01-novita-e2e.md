## 运行方式

需要 Python 3、Go、Node.js、Git，以及包含 Node.js、Codex、Git、gh 的 Novita worker template。模板构建见 [E2B runner 文档](2026-11-01-e2b-runner.md)。准备 Novita API key 文件和能在远端使用的 GitHub token 文件；后者需要目标仓库的 Contents 与 Pull requests 读写权限。

旧 baseline 分支已经清理。完整 PR 模式需要先从已验证的基线 commit 准备新的隔离目标分支；`--base-ref` 必须是实际存在的分支名，不能使用 commit SHA 创建 PR。

```sh
git fetch origin fe5427e1ce9dc9357782dd5a25eab4f8ae560da7
git push origin fe5427e1ce9dc9357782dd5a25eab4f8ae560da7:refs/heads/codex/e2e-cart-baseline-UNIQUE
make frontend-build
go build -o /tmp/cloudpilot-e2b-server ./cmd/cloudpilot
python3 scripts/e2e-novita.py \
  --binary /tmp/cloudpilot-e2b-server \
  --key-file /workspace/.novita-key \
  --github-token-file /workspace/.github-e2e-key \
  --template YOUR_TEMPLATE_ID \
  --repository BingyanStudio/CloudPilot \
  --base-ref codex/e2e-cart-baseline-UNIQUE \
  --head-ref codex/e2e-novita-cart-fix-UNIQUE \
  --output-dir /tmp/cloudpilot-novita-e2e-UNIQUE
```

每次使用新的 baseline、head ref 和输出目录。默认模式会由 sandbox 中的 agent 推送测试分支并创建 draft PR，保留它供人工检查，不合并；验收后关闭测试 PR，再删除 baseline 和 head 分支。`--no-pr` 可以直接使用上述基线 commit 作为 `--base-ref`，验证公开仓库的本地修复、测试和产物链路；它不传递 GitHub 凭据，也不请求任何远端写入。

脚本生成本次隔离验证的主加密密钥，启动独立的 CloudPilot 服务、SQLite 数据库和随机本地端口，通过管理员登录和配置导入 API 创建 Worker、Workspace、Runner、Pipeline、Input。模型和沙箱 API key 通过资源 API 加密入库，随后向 `/hooks/e2e-feedback` 发送真实 HTTP 请求。同一 idempotency key 重发一次，要求返回相同 event ID，且只产生一个 run。

调度器使用 E2B runner 创建 sandbox。Agent 克隆基线，复现失败，修复购物车，并产出基线日志、修复后日志、补丁和 PR 链接。脚本通过 API 下载产物，保存 run、timeline、日志和持久化 runtime 记录，再关闭会话并向 Novita 查询确认 sandbox 已删除。凭据仅通过进程环境传入，保存的文本证据会过滤已知凭据。

## 独立验收

`report.json` 的 `validationScope` 是 `execution-and-artifact-collection`：其 `success` 表示执行、产物收集和资源清理满足断言。它不会代替以下独立检查：

1. 读取 GitHub PR，确认确实存在、为 draft、base/head 与本次参数一致。
2. 获取实际 head commit，检查只有 `e2e/cart-demo/` 改动，原测试未删改，`npm test` 脚本未绕过测试。
3. 对照下载补丁与实际 PR diff，并在独立 checkout 重新执行 `npm test`。
4. 运行未交给 agent 的额外验收用例：

```sh
CLOUDPILOT_E2E_CART_MODULE=/absolute/checkout/e2e/cart-demo/src/cart.mjs \
  node --test scripts/fixtures/cart.acceptance.test.mjs
```

这些用例覆盖 ASCII 数字字符串、默认数量、显式零、非法输入、安全整数边界和输入不可变性。测试前应确认原缺陷基线会失败，避免只验证 agent 自己新增的测试。
